# Migration From the Previous Gemini Harness

The previous harness was intentionally lightweight. This version is governance-oriented and modeled after the stronger rule/skill architecture used in the supplied reference project.

Major differences:
- 33 permanent rules instead of a small list.
- explicit task/change classification
- Claims vs Reality model
- permanent architectural invariants
- ADR lifecycle
- independent architectural verifier
- subsystem-specific engineering skills
- RE/hardware/game-engine workflows
- multi-agent orchestration
- test and runtime evidence gates
- migration/legacy governance
- dependency and technology lifecycle
- release/update governance
- configuration/state lifecycle
- plugin governance
- performance measurement governance
- Git safety
- explicit AI stop conditions

The goal is not to make Gemini "more verbose". The goal is to make it operate through repeatable engineering procedures and enforce boundaries.
