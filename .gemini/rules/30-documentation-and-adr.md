# Documentation and ADR Governance

Architecture documentation describes current architecture.

ADR documents why important decisions were made.

Create an ADR for:
- subsystem ownership changes
- public ABI
- major dependency choice
- plugin architecture
- memory model
- CPU execution model
- GPU architecture
- release/update architecture
- compatibility contract
- migration strategy
- major technology replacement

Never rewrite historical ADRs to erase previous decisions.

Supersede them.
